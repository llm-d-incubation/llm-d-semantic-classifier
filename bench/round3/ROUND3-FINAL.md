# Round 3 — final: Praxis, llm-d and vLLM Semantic Router, all with llm-d-sc

**Cluster:** CoreWeave *waldorf* · **Branch:** `v0.2-staging` · **757 captured runs**
**Config:** llm-d-sc 16 workers / `RAYON_NUM_THREADS=1` / 16 CPU · frozen 200k-utterance corpus

This supersedes the earlier round-3 knee claims, which were withdrawn. Every
number here comes from the corrected instrument; the defects that produced the
withdrawn numbers are listed at the end so the correction can be checked rather
than taken on trust.

---

## ⚠ Headline: classifier saturation is INVISIBLE — and looks like a speed-up

Above the classifier's capacity the gateway does not queue and does not error. It
**fails open**, and requests bypass classification entirely. Measured directly by
comparing gateway request counts against llm-d-sc's own served counter:

| Offered rate | Requests reaching the classifier | p50 |
|--:|--:|--:|
| 500 rps | **60.2 %** | 511.27 ms |
| 4,000 rps | **17.8 %** | **2.00 ms** |

At 4,000 rps, **82 % of requests are never semantically routed.** Meanwhile every
signal an operator watches says the system is healthy and *improving*:

* throughput tracks the offered rate exactly — no saturation;
* error rate is **zero**;
* p50 *improves by 250×* (511 ms → 2 ms), because unclassified requests take the
  fast default path.

**Classification coverage must be measured and alarmed on directly.** It cannot be
inferred from latency, throughput or errors — all three improve as coverage
collapses. This is the same fail-open behaviour found in round 1 with the
classifier dead, now quantified under ordinary load.

**Operating consequence:** the classifier's capacity, not the gateway's, sets the
rate at which semantic routing actually happens. On this hardware that is roughly
**450–500 novel classifications/sec per replica** (16 workers, RAYON=1).

## Headline 2 — the knee is set by the miss fraction, not the gateway

All three gateways knee at the *same* offered rate for the same traffic regime:

| Regime | Novel fraction | Praxis | llm-d | vLLM SR |
|---|--:|---|---|---|
| `miss` | 100 % | **250→500** (14×) | **250→500** (13×) | **250→500** (14×) |
| `mix80` | 20 % | **2,000→4,000** (29×) | **2,000→4,000** (26×) | **2,000→4,000** (128×) |
| `hit` | 0 % | none to 8,000 | none to 8,000 | none to 8,000 |

Three independent data paths agreeing is much stronger evidence than the
convergence argument made earlier. The knee position moves monotonically with the
novel fraction, which is what queueing theory predicts when the model forward is
the constrained resource.

Where the gateways *do* differ is **saturation**: vSR/miss falls behind the offered
rate at 500 rps, while Praxis and llm-d never do through 8,000 — because they shed
classification instead (see headline 1).

## Headline 3 — Rayon, re-verified against genuine misses

`RAYON_NUM_THREADS` is never set by llm-d-sc, so Rayon sizes its pool to the CPU
limit and collides with the executor pool — intra-op parallelism fighting
inter-op. Re-measured with every prompt salted so cache misses are guaranteed
(93.8 % and 87.5 % verified miss rates):

| | req/s | p50 | p99 | verified miss rate |
|---|--:|--:|--:|--:|
| **RT=1** | **481.5** | 137.75 ms | 167.43 ms | 93.8 % |
| RT=4 | 148.3 | 482.27 ms | 647.62 ms | 87.5 % |

**RT=1 is 3.25× RT=4.** An earlier isolated single-run diagnostic reported 6.65×
versus the *unset* default; treat the direction as established and that specific
multiple as unconfirmed — the full W × RT surface did not complete.

## Corrected knees — open-loop, hit ratio pinned by construction

Arrival rate is generated by a central scheduler at a true Poisson process, independent of response latency. The hit ratio is fixed by the regime rather than drifting with the rate, and every `miss` arm is salted so its prompts cannot be served from a cache warmed by an earlier run.

## Defects that invalidated the previous knee claims

Listed so the correction can be checked. All were found by cross-checking a
number against something else already known, not by inspection of the summary
statistics — which looked clean throughout.

| Defect | How it was caught | Effect |
|---|---|---|
| Warmup carry-in: workers claimed arrival slots during warmup | excess was exactly `concurrency/window` = 1024/25 = **40.96 rps** on every arm | every offered rate inflated |
| "Poisson" was a jittered grid, not a point process | code read | underdispersed arrivals; no clustering |
| `--context-bytes` ignored in corpus mode | throughput *rose* with context size — physically impossible | context sweep measured nothing |
| `--cache-mode` ignored in corpus mode | hit and miss regimes produced identical curves | regimes were not distinct |
| Cache-miss arms ran at a **4.4 % miss rate** | checked llm-d-sc's own hit/miss counters against the arm's label | miss-path latency understated **12×** |
| A/B compared at concurrency 64 vs 32 | reading my own test config | measured concurrency, not the variable |
| Ad-hoc probes run against a pod a campaign was driving | asked "am I the only load?" | both sets contaminated |

## What is trustworthy, and what is not

**Trustworthy:** the fail-open coverage finding, the knee positions and their
monotonic relationship to novel fraction, the Rayon direction, route-table
cardinality being free through 32 routes, all cache-hit results, and the
`tcp_nodelay` fix (+86 % throughput, p99 40.9 → 1.2 ms).

**Not established:** semantic *correctness* across 32 routes (every cluster
pointed at one backend, so cardinality was measured, not accuracy); CPU parity
between gateways; semantic-cache accuracy at threshold 0.90; the exact Rayon
optimum; behaviour under network impairment, pod loss or rolling updates.
